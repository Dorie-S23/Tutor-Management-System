# Getting Started

How to get the project running locally.

## Prerequisites

- **Node.js 20+** and npm
- Access to the project's **Supabase** project (URL + anon key) — ask a teammate, or point at your own Supabase project for local testing
- *(Optional)* An **Anthropic API key** from [console.anthropic.com](https://console.anthropic.com) — only needed for the "import timetable PDF" feature on the calendar page; everything else runs fine without it

## 1. Clone and install

```bash
git clone https://sdp.ms.wits.ac.za/the-devden/Tutor-Management-System.git
cd Tutor-Management-System
npm install
```

## 2. Configure environment variables

Copy the example file and fill in real values:

```bash
cp .env.example .env
```

```
SUPABASE_URL=
SUPABASE_ANON_KEY=
ANTHROPIC_API_KEY=
PORT=3000
```

- **`SUPABASE_URL`** / **`SUPABASE_ANON_KEY`** — from your Supabase project's **Settings → API**. The variable name matters: both `app.js` and `server/supabaseClient.js` read `SUPABASE_ANON_KEY` specifically — an `.env` with the older `SUPABASE_KEY` name will crash the server on startup with `Missing SUPABASE_URL or SUPABASE_ANON_KEY environment variables`.
- **`ANTHROPIC_API_KEY`** — only required for timetable PDF parsing. Needs an active credit balance on the Console (**Plans & Billing**) to actually respond, not just a valid key.
- **`PORT`** — defaults to `3000` if omitted.

`.env` is gitignored and never committed — each teammate keeps their own.

## 3. Run it

```bash
npm start
```

This runs `server.js`, a thin entry point that loads `app.js` (the actual Express app and all its routes) and serves `public/` as static files. Visit **http://localhost:3000** — it redirects to the login page.

## 4. (Optional) Run the Cloudflare Worker variant

The same `app.js` also runs as a Cloudflare Worker via [Wrangler](https://developers.cloudflare.com/workers/wrangler/), with `worker.js` as the entry point instead of `server.js` (static assets are served by Cloudflare's assets layer there instead of `express.static`):

```bash
npm run dev:worker   # wrangler dev — local Workers runtime
npm run deploy       # wrangler deploy
```

## 5. Formatting

```bash
npm run format         # auto-fix formatting across the repo
npm run format:check   # check only, no writes
```

CI runs `format:check` on every push (see `.gitea/workflows/format.yml`) — pushing unformatted code fails the pipeline before anything else runs.

## 6. Run this documentation site

This site is a separate app with its own `package.json`:

```bash
cd my-docs
npm install
npm start
```

## Project structure

```
Tutor-Management-System/
├── app.js                     # Express app: middleware + every route mounted here
├── server.js                  # Node entry point — requires app.js, serves public/, listens
├── worker.js                  # Cloudflare Workers entry point — same app.js
├── routes/
│   └── auth.js                 # /api/auth/register, /api/auth/login (Supabase Auth)
├── server/
│   ├── supabaseClient.js       # shared Supabase client used by server/routes/*
│   ├── anthropicClient.js      # Anthropic client (lazily constructed)
│   ├── timetableRoutes.js      # POST /api/timetable/parse — LLM-based PDF parsing
│   └── routes/
│       ├── courses.js
│       ├── tutors.js
│       ├── hourEntries.js
│       ├── courseVolunteers.js
│       └── tutorApplications.js
├── public/
│   ├── html/                   # one .html file per page
│   ├── css/
│   └── js/                     # one script per page, plus shared helpers (nav.js, storage.js, ...)
├── models/User.js              # plain User data class
├── my-docs/                     # this documentation site (independent Docusaurus app)
└── .gitea/workflows/            # format-check, app-deploy, docs-deploy pipelines
```

:::info Two Supabase clients
`app.js` builds its own Supabase client and attaches it to every request as `req.supabase` (used by `routes/auth.js`). Separately, `server/supabaseClient.js` exports its own client instance, imported directly by everything under `server/routes/`. Both read the same `SUPABASE_URL`/`SUPABASE_ANON_KEY`, so they behave identically — it's just two instantiations instead of one shared one.
:::

## Troubleshooting

- **`Missing SUPABASE_URL or SUPABASE_ANON_KEY environment variables`** on startup — check the exact variable name in your `.env` matches `.env.example`. This has bitten the team before after a merge silently renamed the expected variable.
- **Login returns `401 Invalid login credentials`** — either the account was never actually registered (go through `register.html` first), or the email/password doesn't match what was registered. Check the Supabase dashboard's **Authentication → Users** if you're not sure an account exists.
- **Uploading a timetable PDF fails with a billing error** — `ANTHROPIC_API_KEY` needs a funded balance on the Console; the rest of the app works without it.
