# Client Meeting Minutes

Record of meetings with the project's client/supervisor, kept as evidence of process for the course's Project Methodology requirement.

## Sprint 1

### Meeting 1

**Date:** 12 August 2026 · **Meeting Type:** Client Meeting
**Attendees:** Tagona Danha, Mkateko Chauke, Dorsa Shahrokh, Mutsawashe Njowa, Matthew Purkiss
**Purpose:** Documentation site requirements and Sprint 1 documentation

#### 1. Documentation Site

The team discussed the requirements for the project documentation site, including the expectations outlined in the brief and rubric. The documentation site should be well-designed and contain substantial, non-trivial content.

The team discussed the requirement for the documentation site to be publicly accessible and noted that the public URL should be tested, including through an incognito window, to ensure that it can be accessed correctly.

#### 2. Documentation Content

The required documentation for Sprint 1 was discussed in detail. The team went through the different sections that need to be included, including:

- Problem statement and project overview
- Tiered requirements list covering basic, intermediate, and advanced requirements
- Architecture overview and diagram
- Technology stack and reasoning behind the chosen technologies
- Database schema and ERD
- API design and endpoint documentation
- Development setup guide
- Project and Git methodology
- Meeting minutes and stakeholder log
- AI usage attribution log

#### 3. Documentation Platform and Deployment

Possible technologies and deployment options for the documentation site were discussed. The team considered suitable documentation frameworks such as Docusaurus, MkDocs with the Material theme, or mdBook, together with deployment through GitHub Pages or Cloudflare Pages using a CI workflow.

The team also noted that Notion should not be used as the documentation platform due to the project requirements.

#### 4. Action Items

- Ensure all required Sprint 1 documentation is included.
- Select and configure an appropriate documentation framework.
- Deploy the documentation site publicly.
- Test the documentation URL to confirm accessibility.
- Continue developing the required documentation sections.

#### 5. Conclusion

The meeting focused primarily on understanding the documentation site requirements and ensuring that the team was aware of the content and technical requirements expected for Sprint 1.
